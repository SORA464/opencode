# M4.30 — Deletion Rule

## 1. Deletion Policy

Do not delete old composition code because the new design looks cleaner.

Delete only when:

- [ ] New path is authoritative
- [ ] All consumers migrated
- [ ] Parity proven
- [ ] Regression protection exists
- [ ] Rollback remains possible through release process
- [ ] Removal is documented

## 2. Deletion Checklist

Before deleting legacy composition code:

- [ ] New path is authoritative
- [ ] All consumers migrated
- [ ] Parity proven
- [ ] Regression protection exists
- [ ] Rollback remains possible through release process
- [ ] Removal is documented
